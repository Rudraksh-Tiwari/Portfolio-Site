Clarifi

Live

AI financial copilot — full-stack, deployed on AWS

Turns a raw bank statement into structured financial insight: parses the file, categorises every transaction, flags anomalies, forecasts next month, and answers natural-language questions grounded in the user's own history through a per-user vector index.

Testing against a real Indian bank export rather than a clean sample CSV broke the categoriser immediately: because nearly every line in an Indian statement contains UPI, treating the payment rail as a category keyword collapsed roughly 87% of spending into one bucket. Separating merchant identity from payment mechanism restored a real breakdown.

The anomaly detector was rebuilt for the same reason. An Isolation Forest with a forced contamination quota has to flag a fixed share of transactions whether or not anything is wrong. Replacing it with log-scaled per-category robust z-scores (median and MAD) took the same statement from 13 false positives to 5 flags, each carrying a plain-language reason — and let an ordinary month legitimately return nothing at all.

FastAPI · React 19 · PostgreSQL · ChromaDB · Groq Llama 3.1 · JWT · nginx · EC2

Loan Risk Analyzer

Credit decisioning with explainable ML

Predicts loan approval across a 45,000-applicant dataset and explains each decision in plain English. SHAP attributes the model's reasoning to specific applicant features; an LLM turns that attribution into the sentence a customer would actually be told.

XGBoost was selected over logistic regression and random forest on AUC-ROC (0.978 against 0.953 and 0.974) and on minority-class F1 — the class that matters, since approving a bad loan costs more than declining a good one.

Python · XGBoost · SHAP · Groq Llama 3.3 70B · Streamlit

taskq

In progress

A distributed task queue, built from first principles

A background job system in the spirit of Sidekiq and Celery, with the reliability machinery written by hand rather than delegated to a library: atomic job claim, crash recovery, retries with backoff, and a dead-letter queue.

Anyone can call an existing library's enqueue(). The harder thing is building the guarantee underneath it — that once a job is accepted it runs to completion even if the worker is killed mid-execution. That guarantee is the whole project. The FIFO layer is a Redis list driven by atomic LPUSH / BRPOP, so concurrent workers can enqueue and claim without losing or duplicating a job.

Python · Redis · Docker · FastAPI

SeatLock

In progress

Concurrency-safe ticket booking

One hard problem: two people click the same seat in the same millisecond — exactly one gets it, and nobody is ever double-booked. Everything else in the system exists to serve that sentence.

Two layers of defence. A Redis hold with a TTL is fast and optimistic — it greys the seat out live for everyone, but cannot survive a crash on its own. The actual guarantee is a Postgres SELECT … FOR UPDATE row lock at checkout, so two racing payments cannot both win. An idempotency key means a double-clicked "Pay" never books twice.

Spring Boot 3 · PostgreSQL · Redis · STOMP WebSockets · React + TypeScript
